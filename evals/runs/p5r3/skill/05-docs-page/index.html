Parsing and formatting

Turn strings into dates with parse, and dates back into strings with format.

Updated 12 Oct 20266 min readApplies to Quill 3.x
On this page

    01Overview#

    Quill dates are immutable values. Two functions move them across the string boundary: parse(input, format?) returns a QuillDate, and format(date, pattern) returns a string. Neither mutates its input, and neither depends on global state other than the locale you have loaded.

    JavaScript
    import { parse, format } from 'quill'

const d = parse('2027-03-14')
format(d, 'D MMMM YYYY')   // "14 March 2027"

    02Parsing strings#

    With no format, parse accepts ISO 8601 only. Anything else needs a pattern, built from the tokens in the format token table.

    ISO 8601 strings#

    Date-only, date-time and offset forms all work. A string without an offset is read in the local zone.

    JavaScript
    parse('2027-03-14')                // local midnight
parse('2027-03-14T09:30')          // local 09:30
parse('2027-03-14T09:30:00Z')      // UTC 09:30
parse('2027-03-14T09:30+05:30')    // 04:00 UTC

    With an explicit format#

    Pass a pattern as the second argument. Tokens must match the input exactly, including padding: DD requires two digits, D accepts one or two.

    JavaScript
    parse('14/03/2027', 'DD/MM/YYYY')
parse('Mar 14, 2027 9:30 PM', 'MMM D, YYYY h:mm A')
parse('1805894400', 'X')            // Unix seconds

    Gotcha: ambiguous dates

    parse('03/04/2027') without a format is not ISO, so it throws in strict mode and is read month first in loose mode. That is 3 April, even if your reader meant 4 March. Always pass a pattern for non-ISO input.

    Strict and loose mode#

    By default parse is strict: invalid or leftover input throws a QuillParseError. Set { strict: false } to ignore trailing text and to roll out-of-range fields forward instead of throwing.

    JavaScript
    parse('31/02/2027', 'DD/MM/YYYY')
// throws QuillParseError: day 31 is out of range for February

parse('31/02/2027', 'DD/MM/YYYY', { strict: false })
// 3 March 2027

    Trying several formats#

    Give an array and Quill returns the first pattern that matches the whole input. Order them from most to least specific.

    JavaScript
    const formats = ['YYYY-MM-DD', 'DD/MM/YYYY', 'D MMM YYYY']
parse('14 Mar 2027', formats)   // matches the third

    03Formatting dates#

    format(date, pattern) replaces each token with its value in the active locale and zone. Anything that is not a token is copied through unchanged.

    JavaScript
    const d = parse('2027-03-14T21:05:09')

format(d, 'YYYY-MM-DD')          // "2027-03-14"
format(d, 'ddd, D MMM')          // "Sun, 14 Mar"
format(d, 'h:mm A')              // "9:05 PM"
format(d, 'HH:mm:ss.SSS')       // "21:05:09.000"

    Presets#

    Named presets follow the locale's conventions, so you do not hard-code order or separators.

    JavaScript
    format(d, 'L')    // "14/03/2027" (en-GB)  "03/14/2027" (en-US)
format(d, 'LL')   // "14 March 2027"
format(d, 'LLL')  // "14 March 2027 21:05"
format(d, 'LT')   // "21:05"

    04Format tokens#

    The same tokens work in both directions. Examples use 14 March 2027, 21:05:09, in en. Tokens marked locale change with the active locale.

    Escaping literal text#

    Wrap text in square brackets to stop letters being read as tokens.

    JavaScript
    format(d, '[Week of] D MMM')   // "Week of 14 Mar"
format(d, 'D MMM [at] HH:mm')   // "14 Mar at 21:05"

    Gotcha: MM is not mm

    Tokens are case sensitive. MM is the month and mm is the minute, so 'YYYY-mm-DD' prints the minute where the month should be and raises no error.

    05Locales and zones#

    Month and weekday names, A and the presets come from the active locale. Load one and pass it per call, or set it globally.

    JavaScript
    import fr from 'quill/locale/fr'

format(d, 'dddd D MMMM', { locale: fr })        // "dimanche 14 mars"
format(d, 'HH:mm Z', { zone: 'Asia/Kolkata' })   // "02:35 +05:30"

    Parsing uses the local zone unless the input carries an offset or you pass zone. See Time zones for conversion rules.

    06Handling errors#

    Strict parsing throws QuillParseError with the failing token in error.token and the offset in error.index. If you would rather branch than catch, use tryParse, which returns null on failure.

    JavaScript
    const d = tryParse(input, 'DD/MM/YYYY')
if (d === null) return showError('Use the format DD/MM/YYYY')
