Parsing and formatting

Turn a string into a Quill date with parse, and a date back into a string with format. Both take the same tokens.

Applies to quill 3.0 and laterReading time 7 minUpdated 28 Oct 2026

JavaScript
import { parse, format } from 'quill'

const d = parse('14/03/2027', 'DD/MM/YYYY')
format(d, 'dddd, D MMMM YYYY') // "Sunday, 14 March 2027"

Parsing strings

parse(input, format?, options?) returns a QuillDate. It never throws: bad input gives you an invalid date that you can test with d.isValid().

ISO 8601 input

With no format, Quill accepts ISO 8601 and nothing else. That covers dates, date-times, and strings that carry an offset.

JavaScript
parse('2027-03-14')                  // local midnight
parse('2027-03-14T09:30:00')         // local time
parse('2027-03-14T09:30:00+05:30')   // fixed offset, kept as given
parse('2027-03-14T04:00:00Z')        // UTC

Input with a format

Anything else needs a format string as the second argument. The tokens describe the input, in order, and every character in the format that is not a token must appear in the input as written.

JavaScript
parse('14/03/2027', 'DD/MM/YYYY')
parse('March 14, 2027 9:30 PM', 'MMMM D, YYYY h:mm A')
parse('1805312400', 'X')              // Unix seconds

Gotcha: month first, unless you say otherwise

Without a format, parse('03/04/2027') is not ISO, so it returns an invalid date. With { loose: true } it reads the string as March 4, never 3 April. If your users write day first, pass 'DD/MM/YYYY' every time.

Strict and loose mode

By default parse is strict: the input has to match the format exactly, including padding. '3/4/2027' does not match 'DD/MM/YYYY'. Pass loose: true to let single-digit values through and to ignore extra whitespace.

JavaScript
parse('3/4/2027', 'DD/MM/YYYY').isValid()                   // false
parse('3/4/2027', 'DD/MM/YYYY', { loose: true }).isValid()  // true
parse('31/02/2027', 'DD/MM/YYYY', { loose: true }).isValid() // false: no 31 Feb

Loose mode relaxes padding, not meaning. A date that does not exist stays invalid.

Formatting dates

format(date, pattern, options?) returns a string. Tokens are replaced; everything else is copied through. You can also call it as a method: d.format(pattern).

JavaScript
const d = parse('2027-03-14T21:05:09')

format(d, 'YYYY-MM-DD')          // "2027-03-14"
format(d, 'D MMM YYYY, h:mm A')  // "14 Mar 2027, 9:05 PM"
format(d, 'HH:mm:ss')            // "21:05:09"
format(d)                        // "2027-03-14T21:05:09+00:00" (ISO by default)

Gotcha: MM is month, mm is minutes

Case matters in every token. format(d, 'HH:MM') prints the hour and the month, so at 21:05 on 14 March it gives 21:03. It looks plausible, which is why it ships. Write 'HH:mm'.

Escaping literal text

Letters that happen to be tokens will be replaced. Wrap literal text in square brackets and Quill copies it through untouched, in both parse and format.

JavaScript
format(d, 'D MMMM [at] h:mm A')   // "14 March at 9:05 PM"
format(d, '[Q]Q YYYY')            // "Q1 2027"
parse('Week of 2027-03-14', '[Week of] YYYY-MM-DD')

Without the brackets, at would print the meridiem token a followed by a literal t.

Locales

Month names, weekday names, Do and the meridiem come from the active locale. Quill ships English only; load others as packs and pass one per call or set a default.

JavaScript
import { format, setDefaultLocale } from 'quill'
import hi from 'quill/locales/hi'
import de from 'quill/locales/de'

format(d, 'dddd, D MMMM', { locale: de })  // "Sonntag, 14 März"

setDefaultLocale(hi)
format(d, 'MMMM')                          // "मार्च"

The locale also decides which names parse accepts. Parsing 'März' with the English locale gives an invalid date.

Handling invalid input

An invalid date formats as the string "Invalid date" instead of throwing, so check first when the input comes from a user.

JavaScript
const d = parse(input, 'DD/MM/YYYY')

if (!d.isValid()) {
  // d.invalidReason is one of 'format', 'range' or 'locale'
  showError(`Use the form DD/MM/YYYY (${d.invalidReason})`)
} else {
  save(format(d, 'YYYY-MM-DD'))
}

Store ISO, display local

Save dates in ISO form and format them only at the edge, where you know the reader's locale. Round-tripping a display format back through parse is how 03/04 bugs happen.
