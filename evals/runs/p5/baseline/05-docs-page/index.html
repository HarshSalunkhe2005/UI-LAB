    Parsing and formatting

    Turn strings into Quill dates, and dates back into strings, without surprises.

    Updated for v3.2 · 6 min read
    On this page

      Parsing basics

      Pass a string to quill.parse() and you get back a Quill instance. With no format given, Quill accepts ISO 8601 strings and nothing else, so behaviour is the same in every browser and Node version.

      JavaScript
      import { quill } from "quill-dates";

const a = quill.parse("2026-03-04T09:30:00Z");
const b = quill.parse("2026-03-04");

a.isValid(); // true
quill.parse("not a date").isValid(); // false, never throws

      Invalid input never throws. Check isValid() before using the result, or pass { throw: true } if you prefer exceptions.

      Gotcha: date-only strings are local, not UTC

      quill.parse("2026-03-04") gives midnight in the local time zone. The built-in Date treats the same string as UTC. If you compare the two across time zones, set { zone: "utc" } explicitly.

      Parsing custom formats

      Give parse a format string built from the tokens below and Quill reads exactly that layout.

      JavaScript
      quill.parse("04/03/2026", "DD/MM/YYYY");
quill.parse("Mar 4, 2026 9:30 PM", "MMM D, YYYY h:mm A");

// Try several layouts, first match wins
quill.parse(input, ["YYYY-MM-DD", "DD/MM/YYYY"]);

      Strict mode

      By default Quill is forgiving: "31/02/2026" rolls over to 3 March. Turn on strict mode to reject anything that does not round-trip.

      JavaScript
      quill.parse("31/02/2026", "DD/MM/YYYY").isValid();                  // true  (rolled over)
quill.parse("31/02/2026", "DD/MM/YYYY", { strict: true }).isValid(); // false

      Formatting

      Call .format() with a token string. Without arguments it returns ISO 8601 in the date's own zone.

      JavaScript
      const d = quill.parse("2026-03-04T21:30:00");

d.format();                       // "2026-03-04T21:30:00+05:30"
d.format("dddd, MMMM D");          // "Wednesday, March 4"
d.format("h:mm A");                // "9:30 PM"

      Format tokens

      Tokens are case-sensitive. MM is month, mm is minute.

      TokenOutputExample
      Year
      YYYYFour-digit year2026
      YYTwo-digit year26
      Month
      MMMMFull month nameMarch
      MMMShort month nameMar
      MMMonth, zero-padded03
      MMonth number3
      Day
      DDDay of month, zero-padded04
      DDay of month4
      ddddFull weekday nameWednesday
      dddShort weekday nameWed
      Time
      HHHour, 24-hour, zero-padded21
      hHour, 12-hour9
      mmMinute, zero-padded30
      ssSecond, zero-padded00
      SSSMilliseconds000
      AAM or PMPM
      Zone
      ZOffset with colon+05:30
      ZZOffset without colon+0530
      zZone abbreviationIST

      Escaping literal text

      Wrap words in square brackets so Quill does not read them as tokens.

      JavaScript
      d.format("[Week of] MMM D"); // "Week of Mar 4"
d.format("h [sharp] A");      // "9 sharp PM"

      Locales

      Month and weekday names follow the active locale. Set it globally or per call; the per-call value wins.

      JavaScript
      d.format("dddd D MMMM", { locale: "fr" }); // "mercredi 4 mars"
d.format("dddd D MMMM", { locale: "de" }); // "Mittwoch 4 März"

quill.setLocale("de"); // default for everything after

      Relative time

      For "3 hours ago" style output use fromNow() or compare against another date with from().

      JavaScript
      quill.now().subtract(3, "hours").fromNow(); // "3 hours ago"
a.from(b, { short: true });                      // "2d"

      Troubleshooting

      If isValid() is false, call .invalidReason() for a short code such as "unmatched-token" or "out-of-range". Most failures are a format string that does not match the input's separators or case.
