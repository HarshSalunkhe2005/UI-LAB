01 / Selected work

Four projects. Each one had a number that needed to move.

2024 · Logistics SaaS

Shipment ledger

Operations grid for freight forwarders.

Problem

A 112,000-row shipment table froze for four seconds on filter, and screen readers announced it as one long list of unlabelled cells.

What I did

Replaced the DOM table with a windowed grid that keeps true table roles, aria-rowindex and a roving tabindex. Moved sorting off the main thread. Wrote the keyboard map with their ops team before writing any code.

4.1s → 90msFilter response on the full dataset. Passed an external WCAG 2.1 AA audit with zero blockers.
  • React
  • TypeScript
  • Web Workers
  • NVDA / VoiceOver testing

2023 · Public health agency

Outbreak dashboard

Weekly surveillance charts for clinicians and press.

Problem

Charts were screenshots exported from a BI tool. Unreadable on phones, invisible to assistive tech, and a legal risk under public-sector accessibility rules.

What I did

Built a small SVG charting layer with text alternatives generated from the data, a table view behind a toggle, patterns as well as colour, and a keyboard-driven point inspector. Documented it so analysts could add charts without me.

31 chartsRebuilt in six weeks. The agency's analysts have since added 14 more without a developer.
  • SVG
  • d3-scale
  • Web Components
  • Colour-blind simulation

2022 · Fintech, Series B

Reconciliation workbench

Matching bank lines to ledger entries, all day.

Problem

Finance analysts spent most of a shift dragging rows between two panes. Several had RSI. One analyst who used a screen reader couldn't do the job at all.

What I did

Redesigned the workflow around the keyboard: suggestion lists, single-key match and split, undo that actually undoes. Live-region announcements are terse and tested with the analyst who needed them.

−38%Median time per reconciliation batch. The screen-reader user now closes the month-end books on schedule.
  • React
  • XState
  • ARIA live regions
  • Usability sessions

2021 · Open-source / contract

Component audit and repair

A design system with 60 components and 214 known issues.

Problem

A widely used component library had a modal that trapped nobody, a combobox that confused every screen reader, and 212 other things on a spreadsheet no one owned.

What I did

Triaged by user impact, not by count. Rewrote the six components that caused most of the harm, added automated axe checks plus a manual keyboard checklist to CI, and wrote the contribution guide so it stayed fixed.

214 → 9Open issues in four months. The remaining nine are documented with workarounds and owners.
  • TypeScript
  • axe-core
  • Playwright
  • Storybook

02 / About

Small studio of one. Large opinions about tables.

I started as a data analyst, got tired of watching good analysis lost in bad interfaces, and moved into front-end work. That history is why I ask what the number is for before I ask what colour it should be.

I work alone, on purpose. You get the person you speak to on the first call, and you get plain status updates rather than status theatre.

  • Semantics first. If it's a table, it's a table. Custom roles are a last resort.
  • Test with people. Automated checks catch about a third. I do the rest by hand and with real assistive tech.
  • Measure, then claim. Every performance figure on this page came from a profiler, not a hunch.
  • Leave it maintainable. You should be able to fire me and keep the result.
