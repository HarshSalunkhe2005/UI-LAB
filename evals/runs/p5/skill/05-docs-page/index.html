Parsing and formatting

Turn strings into Quill objects and back again, with explicit formats, strict validation and no surprises from the host's locale.

Reading time: 7 minApplies to Quill 3.xUpdated 14 October 2026

Parsing#

Every Quill object starts with quill.parse(). It takes a string and, optionally, a format and an options object, and returns an immutable Quill instance. When parsing fails you get an invalid instance rather than an exception, so check .isValid before using the result.

ISO 8601 strings#

With no format argument, Quill accepts the ISO 8601 family: dates, date-times, week dates and ordinal dates. A string without an offset is read in the zone you pass, or the system zone if you pass none.

JavaScript
import { parse } from 'quill';

parse('2026-10-14');                    // date only, midnight local
parse('2026-10-14T09:30:00Z');          // UTC instant
parse('2026-W42-3');                    // ISO week date
parse('2026-10-14T09:30', { zone: 'Asia/Kolkata' });

Custom formats#

For anything else, pass a format string as the second argument. Tokens are listed in the token reference below. Literal text goes in square brackets so it is not read as tokens.

JavaScript
parse('14/10/2026', 'DD/MM/YYYY');
parse('Oct 14, 2026 9:30 PM', 'MMM D, YYYY h:mm A');
parse('Due on 2026-10-14', '[Due on] YYYY-MM-DD');
Gotcha: MM is month, mm is minute

Tokens are case sensitive. 'YYYY-mm-DD' parses without error and gives you a date in January with the minutes set to the month number. Quill cannot tell you meant months, so use strict: true (below) to catch the shape of the mistake early.

Strict mode and validation#

By default Quill is forgiving: '2026-02-31' rolls over to 3 March. Pass strict: true and the same input returns an invalid instance, with a reason on .invalidReason.

JavaScript
const d = parse('2026-02-31', 'YYYY-MM-DD', { strict: true });

d.isValid;        // false
d.invalidReason;  // "day 31 is out of range for February 2026"

Formatting#

Call .format() with a token string. With no argument it returns an ISO 8601 string with the instance's offset, which is what you want for storage and APIs.

Locale presets#

When the output is for a person, prefer a preset over a hand-written format. Presets follow the locale's own ordering and punctuation, so you don't have to maintain a format per country.

JavaScript
const d = parse('2026-10-14T21:05:09', { zone: 'Europe/London' });

d.format('date.long', { locale: 'en-GB' });   // "14 October 2026"
d.format('date.long', { locale: 'en-US' });   // "October 14, 2026"
d.format('datetime.short', { locale: 'de-DE' }); // "14.10.26, 21:05"

Relative time#

.fromNow() and .from(other) give phrases such as "3 hours ago". They round down, and switch unit at the largest whole unit that fits, so 90 minutes reads "1 hour ago".

  • Pass { style: 'short' } for "3h ago".
  • Pass { numeric: 'auto' } for "yesterday" instead of "1 day ago".
  • Relative output is not stable between calls. Do not use it as a cache key.

Handling errors#

Invalid instances are contagious: arithmetic on them returns another invalid instance, and .format() returns the string "Invalid date". Validate at the boundary, where user input enters, not at the point of display.

JavaScript
function readDueDate(input) {
  const d = parse(input, 'DD/MM/YYYY', { strict: true });
  if (!d.isValid) throw new RangeError(d.invalidReason);
  return d;
}
